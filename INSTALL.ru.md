# Установка

[English](INSTALL.md) · Русский

Инспектор не слушает сеть: он подписчик очереди на шине. Ни адреса, ни сервиса ему не нужно, и
добавление копии не трогает ни узел защиты, ни конфигурацию. Обычно его ставит `placitum-core`.

## Что нужно рядом

| Компонент | Обязателен | Зачем |
| --- | --- | --- |
| NATS | да | очередь `waf.req.json`, аудит, журнал, поколение профилей |
| Redis: буфер | для проверки тел | тело и заголовки приходят локатором, читаются отсюда |
| Контроллер | да | шлёт профили поколением |
| `keeper` | если профиль пишет исходы в наборы | запись идёт запросом на `waf.sets.<набор>.event` |
| `geo` | если запись в набор идёт подсетью или системой | справочник сетей: анонсы и номер системы по адресу |

Внутренний Redis инспектору не нужен.

## Настройки

| Переменная | По умолчанию | Что задаёт |
| --- | --- | --- |
| `NATS_URL` | `nats://127.0.0.1:4222` | шина |
| `REDIS_URL` | из `inspector.conf` | буфер. Пусто — старт с предупреждением, и **каждое тело** считается недоступным; назван, но не отвечает — ошибка старта |
| `WAF_JSON_SUBJECT` | `waf.req.json` | подписка |
| `WAF_JSON_NAME` | `json` | имя в реестре инспекторов и в кадре присутствия |
| `WAF_JSON_QUEUE` | имя | группа очереди на шине |
| `WAF_JSON_PROFILES` | `./profiles`; в образе `/app/profiles` | профили |
| `WAF_JSON_DATA` | `<профили>.applied`; в образе `/var/lib/waf/json` | куда сохраняется применённое поколение |
| `WAF_JSON_RELOAD_EVERY` | `1s` | как часто проверять каталог профилей |
| `WAF_JSON_CONF` | `inspector.conf` в рабочем каталоге, затем `/app/inspector.conf` | очередь и адреса Redis |
| `WAF_JSON_WORKERS` | число ядер | воркеры проверки |
| `WAF_JSON_QUEUE_DEPTH`, `WAF_JSON_QUEUE_FULL`, `WAF_JSON_QUEUE_EXPAND` | `256`, `drop`, `off` | очередь и поведение при переполнении; то же через `inspector.conf` |
| `WAF_JSON_RESERVE_MS`, `WAF_JSON_MIN_BUDGET_MS` | `2`, `2` | запас от дедлайна волны и минимальный бюджет, ниже которого проверка не начинается |
| `WAF_JSON_VERSIONS` | `2` | версии схемы сообщения, которые процесс принимает |
| `WAF_JSON_GEO_ADDR` | пусто | справочник сетей (`host:port`); пусто — записи подсетью и системой отвечают ошибкой |
| `WAF_JSON_GEO_TIMEOUT`, `WAF_JSON_GEO_NEG_MAX` | `500ms`, `0` | ожидание справочника сетей в бюджете сообщения и предел отрицательного кэша |
| `WAF_JSON_LOG` | `info` | стартовый уровень журнала; живьём его переставляет панель |
| `WAF_HEARTBEAT_EVERY` | `4s` | период кадра присутствия |

## Docker Compose

```yaml
services:
  inspector-json:
    image: placitum/json
    scale: 2
    environment:
      NATS_URL: nats://nats:4222
      REDIS_URL: redis://redis:6379
      WAF_JSON_SUBJECT: waf.req.json
      WAF_JSON_NAME: json
      WAF_JSON_GEO_ADDR: geo:50051
      WAF_JSON_LOG: info
    depends_on: [nats, redis]
```

## Проверка

В образе объявлен `HEALTHCHECK`: проба шлёт обычное сообщение по шине с профилем `_probe` и ждёт
`deny` на путь вне его привязок. Зелёный контейнер означает, что живы соединение с шиной, подписка,
скомпилированные контракты и пул воркеров, — TCP-пинг до NATS не сказал бы ни про одно из этого.

```sh
docker exec <контейнер> json-probe --quiet --timeout 1s --uri /healthcheck
```

В журнале при здоровом старте: подключение к шине и буферу, загруженные профили, число
воркеров, затем кадр присутствия каждые четыре секунды.

## Типичные ошибки

- **Пустой `REDIS_URL` не роняет старт**, но делает проверку тел бесполезной: каждое тело
  «недоступно», и решает политика профиля. В журнале это видно предупреждением на старте.
- **Нет профиля — блокировка, а не откат на `default`.** Проверка не тем контрактом — не более мягкая
  проверка, а проверка не того.
- **Поколение подменяет каталог целиком.** Профиль `_probe` при этом не теряется: он подмешивается
  из образа, иначе проверка здоровья краснела бы после первого применения.
