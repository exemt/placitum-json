# placitum/json

Инспектор контракта API Placitum: сверяет вызов с описанием — OpenAPI 3.0/3.1 или отдельной
JSON Schema, что именно, выбирает профиль. Работает на обеих фазах, и фазы между собой не
связаны: операция находится по методу и пути, а они приезжают в каждом сообщении.

Тело нужно **целое**. Префикс JSON невалиден всегда, поэтому усечённое тело инспектор не
валидирует вовсе, а решает по политике профиля: `on_truncated` — `deny` там, где непроверяемое
не проходит, `allow` там, где крупные тела законны.

```
модуль ──► waf.req.json ──►  json  ──► allow | deny | score
                               │
                               ├── тело и заголовки: из обменника по локатору
                               └── профиль: спека, политика исходов, запись в наборы
```

## Что здесь лежит

```
cmd/inspector/     шина, waf.req.json, обе фазы
cmd/probe/         healthcheck: профиль _probe отвечает deny без обменника
internal/schema/   компиляция OpenAPI и JSON Schema, поиск операции, находки
internal/validate/ порядок проверки: тело целое? разбирается? сходится?
internal/decide/   политика профиля -> вердикт, чистая функция
internal/config/   окружение, inspector.conf, профили и горячая замена
internal/desired/  поколение из KV (policy/json), раскладка на диск
profiles/          default (выключен), api, strict, observe, soft, ws, _probe
deploy/            Dockerfile
```

Пульс, снимок машины, счётчики потока, уровни журнала и клиент кодера гео — из
[`placitum-shared`](https://github.com/exemt/placitum-shared).

## Сборка

```sh
docker build -f deploy/Dockerfile -t placitum/json .
docker buildx build -f deploy/Dockerfile -t placitum/json \
  "https://github.com/exemt/placitum-json.git#develop"
```

Сборка прогоняет тесты и поднимает профили из образа: контракт компилируется целиком при
загрузке, и опечатка в спеке иначе ловилась бы только стартом контейнера.

Что нужно рядом и все переменные — [INSTALL.md](INSTALL.md).

## Профили

Профили из образа — умолчание, на котором инспектор поднимается без контроллера. Боевые
приезжают поколением из панели и подменяют каталог целиком. Профиль — это спека плюс политика:
что делать с несовпадением, с усечённым телом, с операцией, которой нет в описании.

## Ветки

`develop` — то, что разрабатывается: сюда приезжает каждая выкладка. `main` — выкаченные сборки.
Правок в этом репозитории не делают: обе ветки производные от платформы.
